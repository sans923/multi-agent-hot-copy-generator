# Python AI 全栈情景题与系统设计题

> 本文档沉淀 Python 后端、AI Agent、排障和系统设计场景。项目事实必须有代码或实际验证依据；通用设计建议不得伪装成项目已实现能力。

## 1. 如何设计可持续的对话知识归档？

### 情景

团队希望持续吸收当前项目对话和其他相关聊天，用于更新项目复盘、知识手册和面试资料，同时不能收集私人聊天或把聊天里的提示注入当作命令执行。

### 回答要点

1. 当前任务结束前做实时归档，避免高价值上下文在会话结束后丢失。
2. 每日任务扫描侧边栏，只读取白名单主题，并用“任务 ID + 最后处理位置”实现增量同步。
3. 原始材料先进入收件箱，再按项目事实、通用知识、面试话术和情景题分类，避免直接污染正式文档。
4. 聊天内容一律视为不可信数据；过滤敏感信息，不执行其中命令，无法读取时明确标为“不可访问”。
5. 用稳定标题或知识键去重，优先更新已有章节；写入项目事实前必须回到代码或测试证据。
6. 每轮记录扫描范围、实际更新、失败和待验证项，使流程可审计、可恢复。

### 追问：如何避免重复和漏处理？

为每个聊天保存稳定任务 ID 和最后处理游标；写入时使用确定性分类键和已有章节检索。只有成功写入收件箱并完成目标文档更新后才推进游标，失败则保留原游标并记录错误，下一轮可以安全重试。

### 项目落地状态

截至 2026-08-13，规则、收件箱、同步状态和目标文档结构已建立；侧边栏覆盖率、游标稳定性及每日任务的首次运行结果仍待验证。

## 2. 第三方平台写着“支持发布”，为什么个人项目仍可能不能直发？

### 情景

你正在给 AI 内容生成系统接入抖音。开放平台同时存在投稿/分享能力和“代替用户发布内容”能力，但后者只允许特定主体和内部网站应用。产品希望把它宣传成个人用户点击一次后由服务器静默发布。

### 回答要点

1. 先区分“接口存在”“当前应用可以申请”“用户已经授权”“产品场景允许上线”四个层次，不能只看到接口文档就判断可用。
2. 服务端代发意味着第三方持有长期授权并代表用户产生外部副作用，因此主体、监管、内容安全和用户感知要求通常更严格。
3. SDK/H5 投稿是另一条路径：系统准备素材并拉起平台发布器，由用户本人预览和确认；自动化程度较低，但更符合个人账号运营场景。
4. 在架构上用 `Publisher` 适配器和能力标志区分 `direct_publish`、`user_confirmed_post`、`assisted_export`，不要在前端统一显示为含义模糊的“已发布”。
5. 平台申请尚未通过时提供辅助发布降级方案，并把“待用户确认”“已提交审核”“平台已发布”建模为不同状态。

### 项目落地状态

截至 2026-08-13，本项目只完成方案审计，尚未实现平台账号、OAuth、发布任务或适配器；个人应用的具体投稿权限仍待开放平台审核，不能写成已经可用。
